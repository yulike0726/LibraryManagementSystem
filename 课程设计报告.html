一、设计内容及要求

设计并实现一个基于 B/S 架构的图书管理系统，采用 Java 作为后端开发语言，HTML5/CSS3/JavaScript 作为前端技术，不依赖第三方框架和数据库系统，通过自实现的 JSON 解析器完成数据的文件持久化。系统需包含以下核心功能：

（1）图书管理模块：实现图书信息的增删改查，支持多条件检索（按书名、作者、ISBN、分类）与多字段排序（支持快速排序、归并排序、冒泡排序三种算法），提供分类管理和库存管理功能。

（2）读者管理模块：实现读者信息的注册、修改、删除与查询，区分学生和教师两种读者类型并自动设置不同的借阅权限（学生最多借5本、借期30天；教师最多借10本、借期60天），并提供基于读者ID和密码的登录认证。

（3）借阅管理模块：实现借书、还书、续借操作，自动校验库存和借阅权限，计算超期天数，统计热门图书排行榜和超期未还列表，区分管理员与读者的操作权限。

（4）系统设计要求：采用 Controller-Service-DAO 三层架构，实现 JSON 数据的文件持久化（不依赖数据库），前端通过 AJAX 技术与后端 RESTful API 通信，界面简洁实用。

二、技术要点

（1）Java 内嵌 HttpServer 实现 HTTP 服务，自实现递归下降 JSON 解析器处理数据序列化与反序列化。

（2）运用 HashMap 实现 O(1) 时间复杂度的图书快速检索，ArrayList 结合自定义 Comparator 实现多字段排序。

（3）实现快速排序（O(n log n)）、归并排序（稳定排序）和冒泡排序（O(n²)）三种排序算法，支持用户在前端自由选择。

（4）采用 Java NIO 进行文件 I/O 操作，数据以 UTF-8 编码的 JSON 文件存储。

（5）前端使用 Fetch API 实现 AJAX 异步数据交互，三线表风格的学术化界面设计。

（6）设计基于 sessionStorage 的登录认证机制，实现管理员和读者两种角色的权限分离。

软件工程专业学生   于利珂

指导教师  李桂青

摘要：本课程设计实现了一个基于 B/S 架构的图书管理系统。系统采用 Java 语言开发后端服务，利用内嵌 HttpServer 提供 HTTP 服务，通过自实现的递归下降 JSON 解析器实现数据的文件持久化存储。前端基于 HTML5、CSS3 和 JavaScript 技术，采用 Fetch API 与后端 RESTful 接口进行异步数据交互。系统包含图书管理、读者管理和借阅管理三大核心模块，实现了图书信息增删改查与多条件检索、读者注册与登录认证、借书/还书/续借及超期检测等功能。系统采用 Controller-Service-DAO 三层架构，数据访问层通过 JSON 文件读写替代传统数据库，降低了部署复杂度。在数据结构方面，系统运用 HashMap 实现图书快速检索，实现了快速排序、归并排序和冒泡排序三种排序算法以支持多字段组合排序，采用枚举和状态机模式管理借阅状态流转。系统区分管理员和读者两种角色，管理员拥有全部管理权限，读者可自助注册、登录并完成借阅操作。经过功能测试和边界条件测试，系统运行稳定，各模块功能完整。

Library Management System

Student majoring in Software Engineering   Yu Like

Tutor  Li Guiqing

Abstract: This course design implements a library management system based on B/S architecture. The system uses Java as the back-end language, employing a built-in HttpServer to provide HTTP services, and implements data persistence through a self-implemented recursive-descent JSON parser with file-based storage. The front-end, built with HTML5, CSS3, and JavaScript, communicates with the back-end RESTful API via the Fetch API for asynchronous data interaction. The system comprises three core modules: book management, reader management, and borrowing management, providing functionalities including book CRUD operations with multi-condition search, reader registration and login authentication, book borrowing/returning/renewal with overdue detection. The system adopts a three-tier Controller-Service-DAO architecture, where the data access layer uses JSON file I/O instead of traditional databases. In terms of data structures, HashMap is used for fast book retrieval, and three sorting algorithms (quick sort, merge sort, and bubble sort) are implemented to support multi-field sorting. Enumeration and state machine patterns are used to manage borrowing status transitions. The system distinguishes between administrator and reader roles, with administrators having full management privileges and readers being able to self-register, log in, and perform borrowing operations. After functional and boundary-condition testing, the system operates stably with complete module functionality.

Key words: Library Management System; Java; JSON Persistence; Sorting Algorithm; B/S Architecture; Three-Tier Architecture

引  言

随着信息技术的飞速发展，高校图书馆的管理方式正逐步从传统的手工登记向数字化、网络化方向转变。一个高效的图书管理系统能够显著提高图书馆的运营效率，方便读者查询和借阅图书，减轻管理人员的工作负担。本课程设计旨在综合运用软件工程专业所学的 Java 程序设计、数据结构、HTML5 等课程知识，设计并实现一个功能完整、架构清晰的图书管理系统。

本系统采用 B/S（Browser/Server）架构，用户通过浏览器即可访问系统，无需安装客户端软件。后端基于 Java 语言开发，利用 JDK 内置的 HttpServer 类提供 Web 服务，不依赖任何第三方框架如 Spring 或 Servlet 容器。数据持久化方面，系统采用自实现的 JSON 解析器配合文件存储方案，避免了数据库系统的安装配置复杂度，使其更易于在教学环境中部署和演示。

1  设计任务与方案选择

1.1  设计任务与指标

1.1.1  设计任务

本课程设计的任务是开发一个完整的图书管理系统，涵盖以下核心功能模块：

图书管理：实现对图书信息（ISBN、书名、作者、分类、出版社、出版日期、库存数量）的增删改查操作，支持按书名、作者、ISBN、分类进行多条件模糊检索，支持按书名、作者、出版日期、可借数量进行多字段排序，支持分类的层级管理。

读者管理：实现读者信息（学号/工号、姓名、院系、读者类型、联系电话）的注册、修改、删除和查询功能，区分学生和教师两种类型并自动配置借阅权限（学生最多借5本、借期30天；教师最多借10本、借期60天）。提供基于读者ID和密码的登录认证，区分管理员与读者两种角色。

借阅管理：实现借书操作（校验库存和借阅上限）、还书操作（自动计算超期天数）、续借操作（每书限续1次），提供借阅记录的多条件查询，统计超期未还图书列表和热门图书排行榜。

1.1.2  设计指标

（1）系统响应时间：普通查询和操作在 1 秒内返回结果。

（2）数据容量：支持至少 1000 条图书记录和 500 条读者记录的存储与检索。

（3）并发支持：内嵌 HttpServer 默认支持多线程并发请求处理。

（4）可维护性：代码采用三层架构（Controller-Service-DAO），层次清晰，易于扩展和维护。

（5）界面可用性：前端界面简洁直观，操作流程清晰，提供友好的错误提示。

1.2  系统方案选择

1.2.1  后端技术方案

方案一：采用 Java Spring Boot + MySQL 数据库。优点：生态成熟，功能强大；缺点：框架依赖重，学习成本高，部署复杂，不符合课程设计1的先修课程约束（课程设计1未涉及数据库和Web框架课程）。

方案二：采用 Java 内嵌 HttpServer + JSON 文件存储。优点：无需额外依赖，仅使用 JDK 内置 API，符合课程要求，部署简单；缺点：文件 I/O 性能不及数据库，不适合大规模并发场景。针对本课程设计的教学场景和功能规模，本系统选择方案二。

1.2.2  数据持久化方案

系统采用 JSON 文件作为数据持久化方案。三个核心实体（图书、读者、借阅记录）分别存储在 books.json、readers.json 和 borrow_records.json 三个文件中。为不引入第三方 JSON 库依赖，系统自实现了一个基于递归下降算法的 JSON 解析器（JsonUtil），支持基本类型、字符串、数组、对象及嵌套结构的序列化与反序列化，同时处理了 UTF-8 BOM 头、枚举类型和静态字段等特殊情况。相较于引入 Gson 或 Jackson 等第三方库，自实现方案更好地体现了对底层序列化原理的理解。

1.2.3  前端技术方案

前端采用原生 HTML5 + CSS3 + JavaScript 实现，不依赖任何前端框架（如 Vue、React）。页面采用三线表风格的表格展示数据，表单交互采用弹窗模式。JavaScript 通过 Fetch API 与后端 RESTful API 进行 JSON 格式的数据交互。登录状态基于浏览器 sessionStorage 实现，在页面加载时通过 auth.js 模块统一校验和渲染导航栏。

1.2.4  排序算法方案

为实现图书列表的多字段排序，系统实现了三种排序算法供用户选择：快速排序（Quick Sort）作为默认算法，时间复杂度 O(n log n)，适合大数据量排序；归并排序（Merge Sort）提供稳定排序特性，适合出版日期等有重复值的字段；冒泡排序（Bubble Sort）时间复杂度 O(n²)，主要用于教学对比，展示不同算法在相同数据上的性能差异。排序通过 Java 泛型和 Comparator 接口实现，支持升序和降序两种方向。

2  系统设计

2.1  系统架构设计

系统采用经典的三层架构模式：Controller（控制层）负责接收 HTTP 请求、解析参数并返回 JSON 响应；Service（业务逻辑层）负责核心业务逻辑的处理，包括数据校验、借阅规则判断、排序算法调用等；DAO（数据访问层）负责 JSON 文件的读写操作，将 Java 对象序列化为 JSON 字符串写入文件，或将 JSON 字符串反序列化为 Java 对象。

系统的网络层基于 Java 内置的 com.sun.net.httpserver.HttpServer 实现。Router 类作为统一的请求分发器，根据 URL 路径和 HTTP 方法将请求路由到对应的 Controller 方法。系统同时提供静态文件服务，前端 HTML/CSS/JS 文件通过 Router 的 serveStaticFile 方法直接返回给浏览器。

2.2  数据模型设计

系统设计了三个核心数据模型，对应三个 JSON 持久化文件。

借阅状态采用状态机模式管理：BORROWED（借出中）为初始状态，还书后变为 RETURNED（已归还），系统检测到超过应还日期则自动标记为 OVERDUE（已超期）。状态转换规则为：BORROWED 可通过还书操作转换为 RETURNED，BORROWED 可通过续借操作延长应还日期并增加续借计数。已归还和已超期状态不可再进行续借操作。

2.4  核心算法与数据结构应用

2.4.1  排序算法的实现与对比

系统在 SortUtil 工具类中实现了三种排序算法，均采用 Java 泛型设计，通过 Comparator 接口实现多字段、升降序的灵活排序。用户在图书管理页面可通过下拉菜单自由选择排序算法。

快速排序（Quick Sort）：以最后一个元素为基准（pivot），通过 partition 操作将小于基准的元素移至左侧、大于基准的元素移至右侧，再递归排序左右子区间。快速排序平均时间复杂度为 O(n log n)，但在最坏情况下（序列已有序）退化为 O(n²)。本实现的 partition 函数采用 Hoare 分区方案，空间复杂度为 O(log n)（递归栈深度）。

归并排序（Merge Sort）：采用分治策略，将列表递归划分为单个元素的子序列，然后自底向上合并有序子序列。归并排序是稳定排序算法，保证相等元素的相对顺序不变，非常适合于出版日期等可能存在重复值的字段排序。时间复杂度恒为 O(n log n)，空间复杂度 O(n)。

冒泡排序（Bubble Sort）：通过相邻元素两两比较并交换实现排序，每轮遍历将最大元素"冒泡"到末尾。通过设置交换标志位实现提前退出优化——若某轮未发生交换，说明序列已有序。时间复杂度为 O(n²)，主要用于教学对比，展示不同算法在相同数据集上的性能差异。

2.4.2  图书检索的数据结构

图书的检索采用了 Java Stream API 的 filter 操作结合字符串模糊匹配。在处理分类筛选时，利用 String.contains() 方法实现层级分类的包含匹配（例如搜索"编程语言"可匹配"计算机科学/编程语言/Java"）。ISBN 和读者 ID 的查询均采用 HashMap 思想，通过 Stream.findFirst() 可达到 O(n) 的线性复杂度；在内存中可通过 HashMap 实现 O(1) 级别的快速索引。

2.4.3  借阅状态机

借阅状态采用枚举（BorrowRecord.Status）结合状态转换规则实现，确保借阅流程的严谨性。BORROWED 状态可通过还书转换为 RETURNED，系统通过 DateUtil.isOverdue() 实时检测是否超期并自动标记为 OVERDUE。续借操作仅对 BORROWED 状态有效，且设置 renewCount 计数器上限为1次，防止无限续借。状态机设计避免了使用复杂的 if-else 嵌套，提高了代码的可读性和可维护性。

2.4.4  JSON 解析器实现

为不引入第三方 JSON 库依赖，系统自实现了一个基于递归下降算法的 JSON 解析器（JsonUtil）。解析器按照 JSON 语法的产生式规则，通过递归调用 parseValue()、parseObject()、parseArray()、parseString()、parseNumber() 等方法实现完整的 JSON 语法解析。序列化方面，通过 Java 反射机制（Class.getDeclaredFields()）获取对象字段并递归序列化，同时过滤静态字段和合成字段以避免枚举常量的无限递归。解析器还特别处理了 UTF-8 BOM（字节序标记 U+FEFF）的去除，确保在不同编码环境下正确解析 JSON 文件。

3  系统调试与测试

3.1  模块单元测试

3.1.1  图书管理模块测试

测试图书的增删改查及检索功能。通过添加 16 本不同类型的计算机科学类图书作为测试数据集，验证了以下场景：

（1）新增图书：输入完整字段的图书信息（ISBN、书名、作者、分类、库存等），验证图书成功添加到系统中，且 availableCount 自动初始化为 totalCount；尝试添加重复 ISBN 的图书，验证系统返回"ISBN已存在"错误提示。

（2）多条件检索：分别以书名关键词"Java"、作者"周志华"、分类"算法"进行搜索，验证返回结果正确匹配且支持模糊搜索；同时设置分类筛选和关键词搜索，验证多条件组合过滤的正确性。

（3）排序功能：分别选择快速排序、归并排序和冒泡排序，按书名、作者、出版日期和可借数量进行升序和降序排列，验证三种算法的排序结果一致。

3.1.2  读者管理模块测试

测试读者的注册、修改、删除及登录功能。添加 7 名学生和 3 名教师共 10 位读者作为测试数据，验证了：读者注册时自动设置默认密码（123456），学生和教师的借阅上限和借阅期限正确设置（学生5本/30天，教师10本/60天），读者通过学号和密码成功登录并获取正确的角色标识和权限信息。

3.1.3  借阅管理模块测试

测试借书、还书和续借的完整业务流程。添加 20 条借阅记录（10条借出中、2条超期、8条已归还）作为测试数据，验证了：借书操作正确校验库存、读者借阅上限和重复借阅限制；还书操作正确恢复库存和读者借阅计数，自动计算超期天数；续借操作正确延长应还日期并限制续借次数。

3.2  集成测试

在系统集成层面，测试了前后端的完整交互流程。从前端登录页面开始，分别以管理员（admin）和读者（2024001）身份登录，验证管理员看到全局统计面板和全部管理菜单，读者看到个人借阅面板和有限的菜单项。管理员通过图书管理页面添加一本新图书，在首页图书列表和检索中验证新图书出现；读者在借阅管理页面输入图书 ISBN 发起借书请求，验证系统自动校验读者权限并在成功后更新库存和读者借阅计数。

3.3  边界条件测试

对系统进行了全面的边界条件测试，主要包括：

（1）库存为 0 时借书：将某图书的 availableCount 设为 0 后尝试借阅，验证系统返回"该图书已全部借出"的错误提示。

（2）读者达到借阅上限：学生读者借满 5 本书后再次借书，验证系统返回"借阅数量已达上限"的错误提示。

（3）重复借阅同一本书：读者尝试借阅自己已借出且未归还的图书，验证系统阻止重复借阅。

（4）删除有未还书的读者：尝试删除还有未归还图书的读者，验证系统返回"该读者还有未归还的图书，无法删除"的错误提示。

（5）续借超限：对同一本已续借过一次的书再次续借，验证系统返回"不能再次续借"的错误提示。

（6）重复归还：对已归还的记录再次执行还书操作，验证系统返回"该图书已归还"的错误提示。

（7）登录错误处理：使用错误的密码、不存在的读者ID、空用户名等场景测试登录接口，验证系统返回相应的错误提示。

所有边界条件测试均符合预期，系统在异常情况下能够给出明确的错误提示信息，不会出现未捕获的异常或数据不一致。

4  总结

4.1  项目完成情况

本课程设计成功实现了一个功能完整、架构清晰的图书管理系统。系统包含图书管理、读者管理和借阅管理三大核心模块，覆盖 16 个 RESTful API 接口和 5 个前端页面（登录页、首页、图书管理、读者管理、借阅管理）。系统实现了管理员和读者两种角色的权限分离，支持读者自助注册和登录。在技术实现上，自实现 JSON 解析器和三种排序算法，并运用了 HashMap、枚举状态机、递归下降解析等多种数据结构与算法，满足了"较难"等级的设计要求。

4.2  团队协作与分工

项目采用 3 人小组协作模式，按照系统模块进行分工：于利珂负责图书管理模块（Book.java、BookDao、BookService、BookController）和系统架构设计（App.java、Router、JsonUtil），肖景匀负责读者管理模块（Reader.java、ReaderDao、ReaderService、ReaderController）和登录认证系统（LoginController），刘洪森负责借阅管理模块（BorrowRecord.java、BorrowRecordDao、BorrowService、BorrowController）和排序算法实现（SortUtil）。前端方面，三人分别负责对应的管理页面开发，公共模块（导航框架、样式、API封装）由团队协商完成。各模块定义了明确的接口边界，通过统一的 JSON 数据格式和 RESTful API 规范实现模块间的松耦合协作。

4.3  收获与反思

通过本次课程设计，项目组成员深入理解了软件工程中从需求分析、系统设计到编码实现、测试调试的完整开发流程。在技术层面，巩固了 Java 面向对象编程、HTTP 协议、JSON 数据格式、B/S 架构和前后端分离的开发模式。在工程层面，体会了模块化设计、接口定义、版本控制（Git）在团队协作中的重要性。同时也认识到系统存在的不足：JSON 文件存储方案在读多写少场景下性能尚可，但不适合高并发和大量数据场景；前端未使用响应式框架，界面交互体验有提升空间。这些问题将在后续学习和项目实践中进一步改进。
