一、设计内容及要求

设计并实现一个基于 B/S 架构的图书管理系统，采用 Java 作为后端开发语言，HTML5/CSS3/JavaScript 作为前端技术，不依赖第三方框架和数据库系统，通过自实现的 JSON 解析器完成数据的文件持久化。系统需包含以下核心功能：

（1）图书管理模块：实现图书信息的增删改查，支持多条件检索（按书名、作者、ISBN、分类）与多字段排序（支持快速排序、归并排序、冒泡排序三种算法），提供分类管理和库存管理功能。

（2）读者管理模块：实现读者信息的修改、删除与查询，区分学生和教师两种读者类型并自动设置不同的借阅权限（学生最多借5本、借期30天；教师最多借10本、借期60天）。读者通过登录页自助注册，管理员在后台统一管理。

（3）借阅管理模块：实现借书、还书、续借操作，自动校验库存和借阅权限，计算超期天数，统计热门图书排行榜和超期未还列表，区分管理员与读者的操作权限。

（4）系统设计要求：采用 Controller-Service-DAO 三层架构，实现 JSON 数据的文件持久化（不依赖数据库），前端通过 AJAX 技术与后端 RESTful API 通信，提供一键启动脚本简化部署。

二、技术要点

（1）Java 内嵌 HttpServer 实现 HTTP 服务，自实现递归下降 JSON 解析器处理数据序列化与反序列化。

（2）运用 HashMap 实现 O(1) 时间复杂度的图书快速检索，ArrayList 结合自定义 Comparator 实现多字段排序。

（3）实现快速排序（O(n log n)）、归并排序（稳定排序）和冒泡排序（O(n²)）三种排序算法，支持用户在前端自由选择。

（4）采用 Java NIO 进行文件 I/O 操作，数据以 UTF-8 编码的 JSON 文件存储。

（5）前端使用 Fetch API 实现 AJAX 异步数据交互，三线表风格的学术化界面设计。

（6）设计基于 sessionStorage 的登录认证机制，管理员和读者共用统一登录入口，系统自动识别角色。

（7）读者信息更新采用部分字段合并策略，仅更新用户传入的非空字段，避免数据意外覆盖。

图书管理系统

软件工程专业学生   于利珂

指导教师  路秀华

摘要：本课程设计实现了一个基于 B/S 架构的图书管理系统。系统采用 Java 语言开发后端服务，利用内嵌 HttpServer 提供 HTTP 服务，通过自实现的递归下降 JSON 解析器实现数据的文件持久化存储。前端基于 HTML5、CSS3 和 JavaScript 技术，采用 Fetch API 与后端 RESTful 接口进行异步数据交互。系统包含图书管理、读者管理和借阅管理三大核心模块，实现了图书信息增删改查与多条件检索、读者注册与统一登录认证、借书/还书/续借及超期检测等功能。系统采用 Controller-Service-DAO 三层架构，数据访问层通过 JSON 文件读写替代传统数据库，降低了部署复杂度。在数据结构方面，系统运用 HashMap 实现图书快速检索，实现了快速排序、归并排序和冒泡排序三种排序算法以支持多字段组合排序，采用枚举和状态机模式管理借阅状态流转。系统区分管理员和读者两种角色，管理员拥有全部管理权限，读者可自助注册、登录并完成借阅操作。读者信息更新采用部分字段合并策略，避免数据意外覆盖。系统提供一键启动脚本，简化编译与运行流程。经过功能测试和边界条件测试，系统运行稳定，各模块功能完整。

关键词：图书管理系统；Java；JSON 持久化；排序算法；B/S 架构；三层架构；统一登录

Library Management System

Student majoring in Software Engineering   Yu Like

Tutor  Lu Xiuhua

Abstract: This course design implements a library management system based on B/S architecture. The system uses Java as the back-end language, employing a built-in HttpServer to provide HTTP services, and implements data persistence through a self-implemented recursive-descent JSON parser with file-based storage. The front-end, built with HTML5, CSS3, and JavaScript, communicates with the back-end RESTful API via the Fetch API. The system comprises three core modules: book management, reader management, and borrowing management, providing functionalities including book CRUD operations with multi-condition search, reader self-registration and unified login authentication, book borrowing/returning/renewal with overdue detection. The system adopts a three-tier Controller-Service-DAO architecture. In terms of data structures, HashMap is used for fast book retrieval, and three sorting algorithms (quick sort, merge sort, and bubble sort) are implemented to support multi-field sorting. Enumeration and state machine patterns manage borrowing status transitions. The reader update logic employs partial-field merging to prevent accidental data overwrites. The system provides a one-click startup script. After functional and boundary-condition testing, the system operates stably with complete module functionality.

Key words: Library Management System; Java; JSON Persistence; Sorting Algorithm; B/S Architecture; Three-Tier Architecture; Unified Login

引  言

随着信息技术的飞速发展，高校图书馆的管理方式正逐步从传统的手工登记向数字化、网络化方向转变。一个高效的图书管理系统能够显著提高图书馆的运营效率，方便读者查询和借阅图书，减轻管理人员的工作负担。本课程设计旨在综合运用软件工程专业所学的 Java 程序设计、数据结构、HTML5 等课程知识，设计并实现一个功能完整、架构清晰的图书管理系统。

本系统采用 B/S（Browser/Server）架构，用户通过浏览器即可访问系统，无需安装客户端软件。后端基于 Java 语言开发，利用 JDK 内置的 HttpServer 类提供 Web 服务，不依赖任何第三方框架。数据持久化方面，系统采用自实现的 JSON 解析器配合文件存储方案，避免了数据库系统的安装配置复杂度。系统还提供了 Windows 一键启动脚本（启动.bat），自动完成编译和端口检测，降低了部署门槛。

1  设计任务与方案选择

1.1  设计任务与指标

1.1.1  设计任务

本课程设计的任务是开发一个完整的图书管理系统，涵盖以下核心功能模块：

图书管理：实现对图书信息（ISBN、书名、作者、分类、出版社、出版日期、库存数量）的增删改查操作，支持按书名、作者、ISBN、分类进行多条件模糊检索，支持按书名、作者、出版日期、可借数量进行多字段排序，支持分类的层级管理。

读者管理：实现读者信息（学号/工号、姓名、院系、读者类型、联系电话）的修改、删除和查询功能，区分学生和教师两种类型并自动配置借阅权限（学生最多借5本、借期30天；教师最多借10本、借期60天）。读者通过登录页自助注册，管理员可在后台编辑读者信息、重置密码。提供统一登录入口，系统自动识别管理员和读者角色。

借阅管理：实现借书操作（校验库存和借阅上限）、还书操作（自动计算超期天数）、续借操作（每书限续1次），提供借阅记录的多条件查询，统计超期未还图书列表和热门图书排行榜。

1.1.2  设计指标

（1）系统响应时间：普通查询和操作在 1 秒内返回结果。

（2）数据容量：支持至少 1000 条图书记录和 500 条读者记录的存储与检索。

（3）并发支持：内嵌 HttpServer 默认支持多线程并发请求处理。

（4）可维护性：代码采用三层架构（Controller-Service-DAO），层次清晰，易于扩展和维护。

（5）界面可用性：前端界面简洁直观，统一登录入口减少用户困惑，提供友好的错误提示。

（6）部署便捷性：提供 Windows 一键启动脚本，自动编译和端口检测。

1.2  系统方案选择

1.2.1  后端技术方案

方案一：采用 Java Spring Boot + MySQL 数据库。优点：生态成熟，功能强大；缺点：框架依赖重，学习成本高，部署复杂。

方案二：采用 Java 内嵌 HttpServer + JSON 文件存储。优点：无需额外依赖，仅使用 JDK 内置 API，符合课程要求，部署简单；缺点：文件 I/O 性能不及数据库，不适合大规模并发场景。针对本课程设计的教学场景和功能规模，本系统选择方案二。

1.2.2  数据持久化方案

系统采用 JSON 文件作为数据持久化方案。三个核心实体（图书、读者、借阅记录）分别存储在 books.json、readers.json 和 borrow_records.json 三个文件中。为不引入第三方 JSON 库依赖，系统自实现了一个基于递归下降算法的 JSON 解析器（JsonUtil），支持基本类型、字符串、数组、对象及嵌套结构的序列化与反序列化，同时处理了 UTF-8 BOM 头、枚举类型和静态字段等特殊情况。

1.2.3  前端技术方案

前端采用原生 HTML5 + CSS3 + JavaScript 实现，不依赖任何前端框架。页面采用三线表风格的表格展示数据，表单交互采用弹窗模式。JavaScript 通过 Fetch API 与后端 RESTful API 进行 JSON 格式的数据交互。登录页面采用统一登录框设计，用户输入账号后系统自动识别管理员或读者身份，无需切换标签页。登录状态基于浏览器 sessionStorage 实现，公共函数（openModal、closeModal、showToast、escapeHtml 等）集中在 api.js 中统一管理。

1.2.4  排序算法方案

为实现图书列表的多字段排序，系统实现了三种排序算法供用户选择：快速排序（Quick Sort）作为默认算法，时间复杂度 O(n log n)；归并排序（Merge Sort）提供稳定排序特性，适合出版日期等有重复值的字段；冒泡排序（Bubble Sort）时间复杂度 O(n²)，主要用于教学对比。排序通过 Java 泛型和 Comparator 接口实现，支持升序和降序两种方向。

1.2.5  读者信息更新策略

读者信息编辑采用部分字段合并更新策略。前端提交的 JSON 对象可能只包含需要修改的字段（如仅修改密码时只发送 {"password":"123456"}），后端 ReaderService.updateReader() 方法先加载现有读者记录，再将请求中非 null 的字段逐一覆盖到现有对象上进行保存。此策略避免了全量替换时未传递的字段被意外清空的风险，尤其保护了 currentBorrows 等系统自动维护的字段不被手动篡改。

2  系统设计

2.1  系统架构设计

系统采用经典的三层架构模式：Controller（控制层）负责接收 HTTP 请求、解析参数并返回 JSON 响应；Service（业务逻辑层）负责核心业务逻辑的处理，包括数据校验、借阅规则判断、排序算法调用等；DAO（数据访问层）负责 JSON 文件的读写操作。

系统的网络层基于 Java 内置的 com.sun.net.httpserver.HttpServer 实现。Router 类作为统一的请求分发器，根据 URL 路径和 HTTP 方法将请求路由到对应的 Controller 方法。系统同时提供静态文件服务，前端 HTML/CSS/JS 文件通过 Router 的 serveStaticFile 方法直接返回给浏览器，并包含目录穿越安全防护。

2.2  数据模型设计

系统设计了三个核心数据模型，对应三个 JSON 持久化文件。

借阅状态采用状态机模式管理：BORROWED（借出中）为初始状态，还书后变为 RETURNED（已归还），系统检测到超过应还日期则自动标记为 OVERDUE（已超期）。BORROWED 可通过续借操作延长应还日期并增加续借计数，每书限续1次。

2.3  API 接口设计

系统采用 RESTful 风格设计 API 接口，前后端通过 JSON 格式进行数据交互。所有 API 响应均包含统一的 JSON 结构：{"success": true/false, "message": "...", "data": ...}。

2.4  核心算法与数据结构应用

2.4.1  排序算法的实现与对比

系统在 SortUtil 工具类中实现了三种排序算法，均采用 Java 泛型设计，通过 Comparator 接口实现多字段、升降序的灵活排序。

快速排序（Quick Sort）：以最后一个元素为基准（pivot），通过 partition 操作分区后递归排序。平均时间复杂度 O(n log n)，空间复杂度 O(log n)。

归并排序（Merge Sort）：采用分治策略，递归划分后自底向上合并有序子序列。稳定排序，时间复杂度恒为 O(n log n)，空间复杂度 O(n)。

冒泡排序（Bubble Sort）：相邻元素比较交换，设置交换标志位实现提前退出优化。时间复杂度 O(n²)，主要用于教学对比。

2.4.2  图书检索与读者信息更新

图书检索采用 Java Stream API 的 filter 操作结合字符串模糊匹配。ISBN 和读者 ID 的查询可通过 HashMap 实现 O(1) 快速索引。读者信息更新采用部分字段合并策略——ReaderService.updateReader() 先加载现有记录，再将请求中非 null 字段逐一覆盖，currentBorrows 等系统字段由借还操作自动维护，不开放手动修改。

2.4.3  借阅状态机

借阅状态采用枚举（BorrowRecord.Status）结合状态转换规则实现。BORROWED 可通过还书转换为 RETURNED，系统通过 DateUtil.isOverdue() 实时检测超期并标记 OVERDUE。续借仅对 BORROWED 状态有效，renewCount 上限为1次。

2.4.4  JSON 解析器实现

系统自实现了一个基于递归下降算法的 JSON 解析器（JsonUtil），按照 JSON 语法产生式规则，通过递归调用 parseValue()、parseObject()、parseArray() 等方法实现完整解析。序列化通过 Java 反射获取对象字段并递归序列化，过滤静态字段和合成字段。特别处理了 UTF-8 BOM 去除。

3  系统调试与测试

3.1  模块单元测试

3.1.1  图书管理模块测试

添加 16 本计算机科学类图书作为测试数据，验证了：新增图书时 availableCount 自动初始化为 totalCount；重复 ISBN 返回错误提示；关键词模糊搜索和分类筛选结果正确；三种排序算法结果一致。

3.1.2  读者管理模块测试

添加 7 名学生和 3 名教师共 10 位读者，验证了：读者注册自动设置默认密码；学生/教师借阅上限和期限正确；统一登录框正确识别管理员和读者身份；部分字段更新（仅修改密码、仅修改姓名等）不覆盖其他字段；管理员重置读者密码功能正常。

3.1.3  借阅管理模块测试

添加 20 条借阅记录，验证了：借书操作正确校验库存和借阅上限；还书操作正确恢复库存和借阅计数，自动计算超期天数；续借操作正确延长期限并限制次数。

3.2  集成测试

分别以管理员和读者身份登录，验证管理员看到全局统计面板和全部管理菜单，读者看到个人借阅面板和有限菜单。完整走通"读者注册→登录→管理员添加图书→读者借书→还书→续借"全流程，前后端数据一致。

3.3  边界条件测试

（1）库存为 0 时借书：返回"该图书已全部借出"。

（2）读者达到借阅上限：返回"借阅数量已达上限"。

（3）重复借阅同一本书：阻止重复借阅。

（4）删除有未还书的读者：返回错误提示。

（5）续借超限：返回"不能再次续借"。

（6）重复归还：返回"该图书已归还"。

（7）登录错误处理：错误密码、不存在ID、空用户名均返回相应提示。

（8）部分字段更新：仅发送密码字段时不影响其他字段。

所有边界条件测试均符合预期，系统在异常情况下给出明确错误提示，无未捕获异常或数据不一致。

4  总结

4.1  项目完成情况

本课程设计成功实现了一个功能完整、架构清晰的图书管理系统。系统包含图书管理、读者管理和借阅管理三大核心模块，覆盖 16 个 RESTful API 接口和 5 个前端页面（统一登录页、首页、图书管理、读者管理、借阅管理）。系统实现了管理员和读者两种角色的权限分离，采用统一登录入口自动识别角色。读者可自助注册，管理员可编辑读者信息和重置密码。读者信息更新采用部分字段合并策略确保数据安全。系统提供一键启动脚本（启动.bat），自动完成编译和端口检测。在技术实现上，自实现 JSON 解析器和三种排序算法，运用了 HashMap、枚举状态机、递归下降解析等多种数据结构与算法。

4.2  团队协作与分工

项目采用 3 人小组协作模式，按模块分工：于利珂负责图书管理模块（Book.java、BookDao、BookService、BookController）和系统架构设计（App.java、Router、JsonUtil），刘洪森负责借阅管理模块（BorrowRecord.java、BorrowRecordDao、BorrowService、BorrowController）和排序算法实现（SortUtil），肖景匀负责读者管理模块（Reader.java、ReaderDao、ReaderService、ReaderController）和登录认证系统（LoginController）。前端方面，三人分别负责对应页面，公共模块（导航、样式、API封装、弹窗管理）由团队协商完成。各模块通过统一的 JSON 数据格式和 RESTful API 实现松耦合协作。

4.3  收获与反思

通过本次课程设计，项目组成员深入理解了从需求分析、系统设计到编码实现、测试调试的完整开发流程。在技术层面，巩固了 Java 面向对象编程、HTTP 协议、JSON 数据格式、B/S 架构和前后端分离的开发模式。在工程层面，体会了模块化设计、接口定义、版本控制（Git）在团队协作中的重要性。系统存在的不足：JSON 文件存储方案不适合高并发场景；前端未使用响应式框架，交互体验有提升空间。这些问题将在后续学习中进一步改进。
